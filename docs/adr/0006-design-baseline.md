# ADR-0006 DESIGN.md は既存の黒基調スタイル参照を出発点に、管制画面向けへ再構成する

- 日付: 2026-09-02
- 状態: 採用
- 関連: harness.md §6 / DESIGN.md / docs/reference/style-reference-harness-io.md

## 文脈

リポジトリ直下に利用者が置いた `DESIGN.MD`（Harness.io のスタイル参照。近黒キャンバス + ミント 1 色アクセント）があり、利用者からは「黒を基調としたモダンで洗練されたデザイン」との指示がある。
一方 harness.md §6 は、管制画面としての性格づけ・状態色の非依存・等幅の用途限定・密度・アクセシビリティを DESIGN.md に含めることを求めている。
また NTFS は大文字小文字を区別しないため、`DESIGN.MD` と `DESIGN.md` を並存させられない。

## 決定

- 既存ファイルは `docs/reference/style-reference-harness-io.md` へ移動し、参照資料として残す。
- `DESIGN.md` を新規に書き、次を引き継ぐ: 近黒の 4 段 surface（`#070707` → `#0d0e12` → `#141418` → 1 段明るい面）、ミント `#70dcd3` を唯一の「光る色」に限定、影を使わず面の明度差と境界線で段差を出す、色を配給する（塗りつぶしボタンは 1 つ）。
- 次は採用しない: 20px の大きな角丸カード、800px のピル状ボタン全般、Calsans / Geist の外部フォント、大文字トラッキングの見出しラベル、ライト面の境界線（`#d9dae5`）を全カードに使うこと。理由は、密度の高い管制画面ではノイズになり、外部フォントはオフライン動作を損なうため。
- 状態は色 + 形 + ラベルで表し、ツール種別には色を与えない。

## 結果

- 「黒基調・ミント 1 色」という利用者の意図を保ちつつ、harness §6.2 / §6.3 の要件を満たす。
- トークンは `DESIGN.md §9` を正とし、`tokens.css` と同期する。
